# 知径 Pathfinder｜当前产品审计与 DemoZ V2 改进方案

> 审计时间：2026-09-13  
> 审计范围：`D:\ClaudeWorks\task-gupiao`、`pathfinder`、`pathfinder copy`  
> 新版目录：`D:\ClaudeWorks\task-gupiao\pathfinder-demoz-v2`

## 1. 结论先行

当前产品已越过“只有原型”的阶段，具备较完整的 Web 页面、P0 真实业务 API、PostgreSQL 数据模型、DeepSeek/Tavily Provider 和 Demo/API 双模式；但它仍处在“可面试演示、部分可联调，尚不能独立部署试点”的阶段。

阻止交付的关键不是页面数量，而是以下事实：

1. 历史报告记录过真实 API E2E 全绿，但本次现场 Docker/数据库未运行，登录接口会因 PostgreSQL 拒绝连接而失败，历史结果不能替代当前回归。
2. Redis、MinIO 过去只存在于文档和环境变量中，没有进入真实业务链路。
3. P2 小队、同伴反馈、机构和内容治理仍主要是页面 Mock，不应表述为完整后端交付。
4. 系统 PRD V2.0 改成“任意主题”，与已确认的“产品经理教材首发”冲突；页面 PRD、UIUX 和 README 也没有同步到同一事实源。
5. 构建通过不等于工程质量达标：旧项目的 ESLint 配置误扫构建目录，源码仍存在条件 Hook 等高风险问题。

因此，本轮不覆盖历史项目，而是建立一个可独立运行的新版本，并把“真实可运行、诚实标注、可复跑验收”作为完成定义。

## 2. 三个目录分别是什么

### 2.1 工作区根目录

根目录主要是训练营教材、股票交易 AI 产品交付物、产品工作流与 SOP，以及 Pathfinder 的上游参考资料。它是方法论与需求输入库，不是一个可直接运行的单体应用。

### 2.2 `pathfinder`

这是较新的活动版本。有效应用位于 `pathfinder/site`，根目录的 `src` 是较早脚手架，不应继续作为开发入口。

它已包含：

- 26 个页面路由、35 个 Route Handler；
- 21 张 Drizzle 表、5 组迁移；
- 账户、路径、节点、费曼练习、评价、笔记、进度等 P0 真实数据链；
- 复习、情境练习、技能、资料库、作品集和搜索的部分 P1/P2 数据链；
- DeepSeek、Tavily 与 Mock Provider；
- 任意主题数据包与跨主题隔离测试。

### 2.3 `pathfinder copy`

它不是更新版，而是较早的稳定快照。后端骨架与 `pathfinder` 接近，但缺少后续的全站主题一致性生成器及对应测试。它适合用于差异回溯，不适合作为新版直接基线。

## 4. 已出现的问题与修复记录

### 4.1 历史已经修复

| 问题 | 根因 | 已采用修复 |
|---|---|---|
| 弹窗内按钮真实点击失效 | 遮罩层 z-index 盖住面板 | 调整层叠关系，并用真实鼠标和 popup URL 验证 |
| 注册链路静默失败 | API 信封被重复解包 | 客户端统一只解包一次 |
| Demo 模式产生真实 AI 请求 | Provider 未按数据源隔离 | Demo 强制 Mock |
| Demo 页面泄漏真实 API 401 | Hook 未限制数据源 | 仅 API 模式启用请求 |
| 中文动态节点打不开 | 路由参数未安全解码 | 增加安全 decode |
| Labs 生成 500 | Prompt 与 Zod 字段类型不一致 | Schema 兼容归一 + Provider 兜底 |
| 201 被错误变成 200 | status 被塞进 meta | response helper 将 status 提升为 Response init |
| 主题内容串台 | 固定产品经理 Demo 内容被复用 | `topic` 强制输入、稳定 `gen-*` ID、Jaccard 隔离断言 |
| 资料库读到公共 Demo 内容 | API 页面读取静态数据 | 建独立表与 user/path 双键隔离 |
| AI 导航测试偶发失败 | 用固定 sleep 等长任务 | 等待真实 URL/目标状态 |

### 4.2 本次现场新发现

| 问题 | 证据/影响 | 本轮处理 |
|---|---|---|
| 当前真实前后端未连通 | 5432/6379/9000 未监听；API 登录连接被拒绝 | 新建自包含 Compose：app + PostgreSQL + Redis + MinIO |
| 历史 Demo E2E 只有 5/8 链路通过 | 路由等待过早、离线文案变更、密钥正则误报 `task-async` | 改为等待 `/home`；同步新文案；密钥正则增加边界和长度 |

## 5. 新版产品方案

### 5.1 定位收口

首发只承诺：

> 面向转行和初级产品经理的 AI 能力内化工作台，以 19 个经审核的产品经理教材节点为骨架，用可核验资源证据、费曼练习和学习反馈，把“看过”变成“能讲清、能应用、能留下证据”。

任意主题的编排代码仍保留，但作为后续实验能力。这样既能保留技术扩展性，也不会在冷启动阶段对所有学科做无法保证的内容质量承诺。

### 5.2 核心差异化

1. **可信骨架而非 AI 随机目录**：路径以教材能力结构为基准，AI 只做个性化排序、节奏与补充。
2. **每一步都有证据**：资源显示来源、等级、检查时间和推荐理由，AI 建议可回到依据。
3. **费曼追问不是普通聊天**：AI 扮演学生，一次追问一个理解缺口，评价绑定当前节点能力目标。
4. **能力证据代替虚假分数**：节点完成、练习表达、情境表现和作品共同构成技能证据。
5. **中断可恢复**：路径、草稿、会话、笔记和复习状态都围绕“回到下一步”设计。

### 5.3 微创新

- 首页只给一个“当前最值得做的任务”，避免仪表盘式信息堆积。
- A/B/C 证据分级同时展示可访问性与版权提示，降低“权威资料”误导。
- 费曼结果用“已讲清 / 待补充 / 尚未覆盖”，不把模型反馈包装成绝对评分。
- 练习草稿区分“本机、同步中、已保存、失败可重试”，不制造假同步。
- 一键角色登录展示新用户、在学者、中断练习者、内容管理员和机构管理员五种真实状态。

## 6. 新版技术方案

```text
Browser
  → Next.js App Router（页面 + Route Handler，模块化单体）
      → PostgreSQL / Drizzle：权威业务数据
      → Redis：AI 限流、幂等与后续任务状态
      → MinIO / S3：私有资料与作品附件
      → DeepSeek Provider：路径、追问、评价
      → Tavily Search Provider：公开资料检索
```

采用模块化单体而不是提前拆微服务，原因是当前目标是试点验证；它能减少部署和数据一致性成本，同时通过 Provider、Service 和表域保持未来拆分边界。

## 9. 新版完成定义

- 代码：typecheck、build、受控 lint 通过；
- Demo：8 条浏览器主链路、主题/教材一致性、角色/租户门禁通过；
- API：真实注册/角色登录 → 路径 → 练习 → 评价 → 笔记通过；
- 文件：上传到 MinIO、数据库落元数据、本人可预签下载、他人不可访问；
- 部署：Compose 可启动，live/ready 可区分进程和依赖状态；
- 安全：客户端、日志和构建产物无密钥；依赖无高危/严重已知漏洞；
- 体验：1440px 与 390px 无横向溢出、无 404/白屏/阻断控制台错误。
