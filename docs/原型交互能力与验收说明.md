# 知径 Pathfinder 原型交互能力与验收说明

## 1. 当前交付层级

当前版本定位为“全栈真实 Demo”，同时满足高保真前端 Demo 的交互要求：

- 前端：Next.js 16、React 19、完整路由、组件与全局状态。
- 后端：Next.js Route Handlers，统一 API 信封、会话鉴权与用户数据隔离。
- 数据：PostgreSQL 保存业务数据，Redis 用于会话/限流/短时预览缓存，MinIO 保存上传文件。
- AI 与搜索：DeepSeek 负责规划与生成，Tavily 负责可追溯的网络检索；均仅由服务端调用。
- 部署：支持 Docker Compose，也支持本机基础设施加生产构建方式运行。

本产品不再单独维护一个静态 HTML 假数据版本，以免评审结论与真实研发实现脱节。

## 2. 设计系统

`DESIGN_SYSTEM=linear（知径双主题适配版）`

- 暗色：近黑画布、半透明边界、表面明度分层与少量青绿色行动色。
- 浅色：不照搬暗色玻璃辉光，改用暖灰画布、柔和阴影、实体层级和低饱和青绿色。
- 字体与密度：紧凑标题、克制字重、8px 栅格；页面在高信息密度下仍保持清晰层级。
- 反馈：状态不仅依赖颜色，同时使用文字标签、按钮状态和 Toast。
- 可访问性：键盘焦点、Esc 关闭、遮罩关闭、Focus Trap、44px 主要触控目标和移动端无横向溢出。

## 4. 本次重点：学习路径工作台

### 4.1 用户问题

原版本能创建多条路径，但列表更像结果展示，用户难以回答三个管理问题：

1. 我有哪些主题，哪个正在推进？
2. 某条路径的时间投入、目标日期和状态怎么调整？
3. 路径暂停、完成、归档后，历史学习资产是否仍然保留？

### 4.2 新增能力

- 四张动态指标卡：路径数、完成节点、平均周投入、跨路径综合完成率。
- 列表/看板双视图；看板卡片可在进行中、暂停、完成、归档之间拖动。
- 关键词搜索、状态筛选、最近活动/进度/目标日期/名称排序和分页。
- 路径详情抽屉、更多操作下拉菜单、编辑弹窗、归档确认弹窗和结果 Toast。
- 编辑路径名称、每周投入与目标日期，保留原学习进度。
- 设置当前路径与主路径；归档主路径时自动选取最近活动的非归档路径作为主路径。
- 归档采用非破坏性状态流转，不删除节点、资料、练习和作品。
- 视图、排序、状态筛选写入 `pf-paths-workbench-v1`，刷新后恢复。

### 4.3 真实接口

`PATCH /api/v1/paths/:pathId`

支持字段：`title`、`weeklyHours`、`deadline`、`status`、`setPrimary`。服务端通过会话解析用户，SQL 使用 `pathId + userId` 做归属校验，其他用户路径统一返回 404。

## 6. 后续建议

1. 将节点级拖动排序做成独立计划编辑模式，保存为不可变计划版本，而不是直接改原节点顺序。
2. 增加 Agent 运行记录页，展示“目标理解—查询规划—来源召回—课程编排—用户确认”的耗时、来源和失败重试。
3. 为路径管理接口增加审计日志和幂等键，便于多人部署后的问题追踪。
4. 将当前路径从浏览器 localStorage 升级为用户偏好表，实现跨设备同步；localStorage 继续作为离线回退。
